## 二、这一版按你的两点要求改了什么

### 要求 1：左侧栏按钮做毛玻璃

从 DSH 的侧栏产物里定位到三个真实按钮类（`cursor:pointer` 规则）：`panelRow`（会话/面板行）、
`newSession`（新建会话）、`iconButton`（图标按钮）——其中 `panelRow` 原本是 `background:0 0` 全透明。

现在它们都是毛玻璃小块：

| 元件 | 效果 |
|---|---|
| `panelRow`（列表行） | 44% 玻璃底 + 紫色描边 + 内高光 + `blur(14px)` 毛玻璃 |
| `newSession`（新建会话） | 同上（并排除 `Content/Label/Shortcut` 子元素，避免子元素也被加框） |
| `iconButton`（图标按钮） | 30% 玻璃底 + `blur(10px)` 轻毛玻璃 |
| `panelActive`（选中行） | 紫→粉渐变底 + 粉色描边 + 左侧 3px 粉色强调条 |

### 要求 2：壁纸不要模糊

**上一版的错误**：我把 `backdrop-filter` 加在了 `sidebarCol`（侧栏列）和 `centerCol`（主区）这两个
**大容器**上——它们几乎覆盖整个窗口，等于把整张壁纸糊成了色块。

**现在**：这两个大容器**一律不加 `backdrop-filter`**，毛玻璃只挂在按钮小块上。
壁纸层本身 `blur: 0`，所以**壁纸始终是清晰的原图**，只有按钮内部才有玻璃质感的模糊。

同时把面板略调实一点（`panelAlpha 0.46→0.52`、`sidebarAlpha 0.34→0.40`），
让文字压在清晰壁纸上也读得清。

## 五点五、设置面板完全不透明（透明度 0%）

DSH 的设置 / 插件页是一个 **800×800 的模态面板**，DOM 标记为 `data-shortcut-modal="settings"`，
背景取自 `--dsw-alias-bg-layer-2`——正是本皮肤改成半透明的那个令牌，所以之前设置面板会透出壁纸。

现在在**面板作用域内**把这些令牌还原成不透明静态色阶：

| 令牌 | 亮色 | 暗色 |
|---|---|---|
| `--dsw-alias-bg-layer-1 / -2 / -3` | `bluish-00`（纯白） | 875 / 850 / 800 |
| `--dsw-alias-settings-card-fill` | `bluish-50` | `bluish-800` |
| 面板自身 `background` | `bluish-00` | `bluish-850` |

同时面板内 `text-shadow: none`（实心背景不需要阴影）。

**注意**：只改了面板本体，**遮罩（mask）保持原样**，所以面板外的背景依然是被压暗的。
想改回半透明：把 `opaqueSettings` 设为 `false`。

自检新增 5 条专门断言：覆盖了设置模态面板、面板背景不含 `color-mix`（即不透明）、
使用不透明静态色阶、面板内无文字阴影、`opaqueSettings: false` 时不输出这些规则。

## 五点六、液态玻璃（按钮 70% 透明 / 对话框 80% 透明）

数值口径与上一节一致：**"透明度 70%" = 不透明度 0.30**。

**左侧栏按钮 = 液态玻璃**（`panelRow` / `newSession` / `iconButton`）：

- 底 = 30% 不透明白的**垂直渐变**（顶部 38%、底部 24%，形成玻璃的光泽起伏）
- `backdrop-filter: blur(20px) saturate(1.8)` —— 强模糊 + 高饱和，这是液态玻璃观感的关键
- 高光边缘：`inset 0 1px 0 #ffffff62`（顶部亮线）+ `inset 0 -1px 0 #ffffff14`（底部微光）
- `border: 1px solid #ffffff42` 白色细描边 + `border-radius: 12px`
- 外阴影 `0 2px 10px rgb(0 0 0 / .10)`

**对话框 = 玻璃（80% 透明）**：

- 目标：`[role="dialog"][aria-modal="true"]:not([data-shortcut-modal="settings"])`
- **刻意排除设置面板**——它按上一轮的要求保持完全不透明，否则这条规则会把它一起变透
- 底 = 20% 不透明的渐变（顶部 26%、底部 16%），面板内的 `--dsw-alias-bg-layer-1/2/3` 一并变玻璃
- `backdrop-filter: blur(25px) saturate(1.8)`、白色描边、顶部高光、`0 18px 50px` 大投影

自检新增 5 条断言：对话框玻璃排除了设置面板、生成了对话框规则、有玻璃模糊、
玻璃底为 20%（即透明度 80%）、有顶部高光。

## 五点七、两级按钮透明度 + 对话框毛玻璃

数值口径不变：**透明度 X% = 不透明度 (100−X)%**。

| 目标 | 透明度 | 玻璃底 | 选择器 |
|---|---|---|---|
| 默认工作区的一级按钮 | 30% | `buttonAlpha: 0.70` | `[class*="panelRow"]`、`newSession`、`iconButton` |
| 工作区里的**单个条目** | 50% | `rowAlpha: 0.50` | `[class*="sessionRow"]` |
| 对话框（毛玻璃） | 70% | `dialogAlpha: 0.30` | `[role="dialog"][aria-modal="true"]:not([data-shortcut-modal="settings"])` |

**"单个条目"是怎么定位的**：`workspace` 包里有**两套** CSS Module——一级是侧栏的
`panelRow`（面板入口），而列表里的每一行来自另一套模块的 `Rows_module_css_default.sessionRow`
（带 `selected` / `menuOpen` / `dropBefore` 等状态类）。两者是不同的东西，所以透明度分开控制。

三者做法仍是液态玻璃：垂直渐变底 + `blur(20px) saturate(1.7~1.8)` + 白色细描边 +
顶部高光（`inset 0 1px 0`）+ 圆角；条目行圆角 10px，一级按钮 12px。

> 工作区分组的容器类（`groupSection`）**没有**纳入，避免分组框与组内条目两层玻璃叠加。
> 若你说的"单个工作区"其实指**分组标题**，告诉我，我把它一起加进来。

## 五点八、左下角个人中心按钮（液态玻璃）

- **当前值：`accountAlpha: 0.80`**（不透明度 80%）
- 变更轨迹：初版透明度 20% => `0.80` → 一度下调到 `0.50`（不透明度 50%）→ 现又调回 `0.80`
- 这块就是侧栏左下角**头像 + 用户名**那个可点入口
- 定位：侧栏底部席位是 **`triggerRow`**；账户插件可往 `settings.launcher` 注册自己的入口，
  未注册时外壳保留回退的 `trigger` 按钮。所以选择器同时覆盖两者：

  [class*="triggerRow"] > :is(button, [role="button"], [class*="trigger"]) :not([class*="triggerLabel"])

## 五点九、输入区（composer）：不透明度 50%

**注意这次说的是"不透明度"**，所以直接就是 `inputAlpha: 0.50`，不做 100−X 换算。

**怎么定位到的**：官方文档提到 `--dsw-elevation-soft` 是"composer 专用"的模糊档，
用它反查 `ui-conversation` 的产物就命中了：

```css
.RlGAzG_card {
  max-width: var(--dsh-composer-card-max-width);   /* 直接叫 composer */
  border-radius: var(--dsw-radius-panel);          /* 28px 大圆角，与截图吻合 */
  background: var(--dsw-specific-input-major);     /* 输入区专用背景令牌 */
}
```

**改法**（两条线，都不依赖类名哈希）：

1. **覆盖专用令牌** `--dsw-specific-input-major`：
   浅色 `bluish-00` / 暗色 `bluish-850` 取 50% 不透明度；
2. **毛玻璃**用 `:has()` 精确命中"含输入框的那张卡"：
   `[class*="card"]:has(textarea, [contenteditable="true"])`
   —— 避免误伤设置卡片、账户卡片等其它 `card`；配白色细描边 + 顶部高光 + `blur(18px)`。

> 顺带修好了我那个扫描脚本的缺陷：它原来只匹配 `const css = "..."`，
> 会漏掉打包后的 `css$6` 这类变量名——正是这个缺陷让我第一次找 composer 时 0 命中。
> 现在正则是 `const css[\w$]* = "..."`，一次就命中了。

## 五点十、用户气泡（透明度 10%）

**叫法**：你发出的消息在对话记录里渲染成的那一条，DSH 官方文档里叫 **用户气泡**（user message bubble）。

**定位**（用 `--dsw-specific-bubble` 反查，一次命中）：

```css
.cJsG2q_bubble {
  background: var(--dsw-specific-bubble);   /* 气泡专用令牌，浅色 deepseek-50 / 暗色 bluish-850 */
  border-radius: var(--dsw-radius-xl);
}
```

- 气泡本体类名后缀 = **`bubble`**
- 所在插件 = `ui-chat`；外层还有 `userRow` / `userStack`（右对齐），以及流程标记 `data-chat-flow-kind="user"`

**改法**：透明度 10% => 覆盖 `--dsw-specific-bubble` 取 **90% 不透明度**
（浅色基于 `deepseek-50`，暗色基于 `bluish-850`），再用 `[class*="bubble"]` 给气泡加毛玻璃、
白色细描边与顶部高光。该令牌只被气泡本体使用，覆盖它不会波及别的表面。

## 五点十一、性能与用量条（不透明度 100%）

**叫法**：composer 下方那一行统计（`⏱ 16 轮 269 步 · 274 tok/s`、`🗄 85.1M tok · 缓存命中 99%`、`◐ 65%`）。
DSH 官方叫 **性能与用量**，由配置项 `ui-chat.performanceUsage` 控制（`compact` / `detailed`，你当前是 `detailed`）。

**结构**（读 `ui-chat` 产物得到）：

```js
const StatsPills = …                      // 组件名
<div data-composer-stats={true}>          // ★ 稳定钩子
  <TimePill … />                          // 轮 / 步 / tok/s
  <UsagePill … />                         // tok 总量 / 缓存命中
</div>
```

它挂在 conversation 包 composer 的 **`.dock`**（`RlGAzG_dock`，`gap:12px` 的居中横排）里，
第三项上下文百分比（`65%`）也在这同一行，但不在 `data-composer-stats` 内部。

**改法**：`[data-composer-stats]`、`.dock`、**dock 的所有直接子元素**、以及 dock 内带 `trigger`
的按钮（= `ContextMeter` 上下文占用环）一起染成同一色，取 `statsAlpha: 1`
（100% 不透明：浅色 `bluish-00` / 暗色 `bluish-850`）+ 10px 圆角。

> **踩过的坑（已修）**：第一版把多选择器字符串直接拼在主题前缀后面，生成了
> `body[data-ds-dark-theme] A, B, C` —— **只有 A 受主题约束**，B/C 在浅色主题下也会套上

> 所有暗色规则的每个逗号分隔选择器都必须以 `body[data-ds-dark-theme]` 开头。

> 定位它花了几轮：我那个扫描脚本连着修了三处才准 ——
> ① 只认 `const css = "..."`（漏 `css$6`）；② 只认双引号（漏反引号模板字符串）；
> ③ 类名正则硬要求前导下划线（漏 `cJsG2q_userRow` 这种无前导下划线的哈希）。
> 现在三项都修好了：任意变量名 + 三种引号 + 从真实 CSS 文本里提类名。

## 五点十二、滚动条（不透明度 100%）

界面里那条"透出壁纸的窄竖条"就是**滚动条轨道**。原因在 `ui-theme` 的滚动条样式里：

```css
::-webkit-scrollbar { width: var(--dsh-scrollbar-width) }          /* 默认 5px */
::-webkit-scrollbar-track { background: 0 0 }                       /* ★ 轨道全透明 */
::-webkit-scrollbar-thumb { background: var(--dsh-scrollbar-thumb) } /* 滑块本来也只是半透明 */
```

**改法**：把轨道和滑块都改成不透明 ——

- `::-webkit-scrollbar-track` 给不透明底色（浅色 `bluish-00` / 暗色 `bluish-850`）；
- `--dsh-scrollbar-thumb` / `--dsh-scrollbar-thumb-hover` 改成不透明的中灰
  （浅色 `bluish-400` / hover `bluish-500`；暗色反过来）。

`scrollAlpha: 1` 即 100%。滚动条**宽度**未改动（仍由 DSH 的 `--dsh-scrollbar-width` 控制）。

## 五点十三、页面内即时开关 + 桌面控制程序

### 页面内小开关（即时，不用重启）

皮肤会往页面注入 `lib/page.js`（独立文件，避免被宿主打包器转译改写）：

- 在 `<html>` 上维护 `data-dsh-dream-skin-wallpaper="off"` 标记，CSS 靠这个标记隐藏壁纸层与遮罩；
- 在界面右下角挂一个 **Shadow DOM** 小药丸，点一下即时切换，可拖动，位置与状态存 localStorage；
- 用 Shadow DOM + `:host{all:initial}` 隔离，DSH 自己的样式改不动它。

CSS 侧新增的关闭态：

```css
html[data-dsh-dream-skin-wallpaper="off"] body::before,
html[data-dsh-dream-skin-wallpaper="off"] body::after { display: none !important }
html[data-dsh-dream-skin-wallpaper="off"] body { --dsw-alias-bg-base: …bluish-00 }      /* 浅色 */
html[data-dsh-dream-skin-wallpaper="off"] body[data-ds-dark-theme] { …bluish-1000 }     /* 暗色 */
```

（关掉壁纸后把底色恢复成不透明，否则会透出 Electron 的窗口底色。）

配置项 `pageToggle`（默认 `true`）控制是否注入这个小开关。

### 桌面程序 `DSH皮肤开关.exe`

用 .NET Framework 自带的 `csc` 编译的**单文件绿色程序**（源码在 `app/MainForm.cs`）：

- 自动定位 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml`（找不到 desktop 就退而找 profiles 下任意含该文件的目录）；
- 自动从**运行中的进程**取 DSH 可执行文件路径，取不到再从常见安装位置兜底；
- **壁纸开/关** = 改 `imageOpacity`（`0` ↔ `0.95`）；
- **皮肤启用/停用** = 给那一段逐行加/去 `# `（用注释，原始内容完整保留）；
- **一键重启 DSH** 让改动生效；
- 自带 `--dump <文件>` **只读**自检模式，便于验证且无副作用。

实测（`--dump`）：`blockFound=True`、`skinOn=True`、`imageOpacity=0.95`、块 27 行、
自动找到 `…\Programs\DeepSeek Harness\DeepSeek Harness.exe`；
**注释 → 取消注释往返完全一致**（不会写坏配置）。

## 七、注意事项

- **每次界面加载会内联约 1.5 MB 的 base64 壁纸**。介意启动变慢就把图压到 500 KB 以内。
- 本次走的是**用户补丁层 insert**，DSH 的「插件」页面里**不会**把它列为已安装组合包。
- 若按钮毛玻璃看起来"太重"，把 `buttonAlpha` 降到 `0.30 ~ 0.36`。
- 若壁纸仍显得发雾，检查 `blur` 是否为 `0`（这是唯一会模糊壁纸的参数）。
